### 안건 2. 공동 헤더 파일 작성

- 팀원 간 모듈 연동을 위해 공통 데이터 구조체 및 함수 API 정의
- `project_types.h`에 센서 샘플, 이벤트 정보, 이벤트 유형 등 공통 자료형 정의
- `system_config.h`에 샘플링 주기, 이벤트 전후 기록 시간, 버퍼 크기 등 공통 설정값 정의
- `docs/api-contract.md`를 통해 모듈별 함수 인터페이스 및 호출 규약 정리
- 센서 데이터는 `SensorSample` 구조체를 통해 통합 관리하는 방향으로 설계
- 이벤트 유형은 비트 플래그를 사용하여 복합 이벤트 표현 가능하도록 설계

### 안건 3. 시스템 동작 및 역할 분담

- Timer Interrupt는 1ms 주기로 발생하며, 센서 데이터는 10ms 간격으로 수집하도록 설계
- 이벤트 발생 이전 5초와 이후 5초의 데이터를 저장하는 블랙박스 구조 적용
- Ring Buffer를 이용하여 최근 센서 데이터를 지속적으로 보관
- 이벤트 발생 시 이전 데이터와 이후 데이터를 하나의 Event Record로 저장
- 모듈별 개발 후 공통 API를 통해 통합하는 방식으로 진행

**역할 분담**

- 윤아: 센서 입력, 필터링, Timer/Interrupt, Ring Buffer, Event Record
- 연경: 이벤트 감지 및 분류, LED/HEX 출력, 알람, KEY/SW 입력, 시스템 상태 관리
- 공동: Main Loop 통합, 하드웨어 연결 및 최종 테스트

## 5. 발생한 문제 및 해결 방안

**문제 1. 모듈별 데이터 및 함수 인터페이스 불일치 가능성**

- **원인:** 팀원별로 기능을 분리하여 개발하므로 공통 자료형과 함수 호출 규칙이 필요함
- **해결 방안:** `project_types.h`, `system_config.h`, `api-contract.md`를 기준으로 공동 인터페이스를 관리

**문제 2. 하드웨어 개발환경 및 인터럽트 구현 방식 확인 필요**

- **원인:** Nios II 전용 컴파일러와 하드웨어 의존 코드로 인해 일반 PC 환경에서 전체 동작 검증이 어려움
- **해결 방안:** 기존 수업 실습의 MMIO 및 Exception Handler 구조를 활용하고, 하드웨어 의존 모듈은 실제 Nios II 환경에서 추가 검증

**문제 3. 실제 센서 채널 및 입력 특성 미확정**

- **원인:** 센서 배선과 하드웨어 입력값 검증이 아직 완료되지 않음
- **해결 방안:** ADC 채널을 설정값으로 분리하고, 하드웨어 연결 이후 센서 입력값과 임계값을 보정
