## 3. 구현 내용

### 작업 1. Audio-in 기반 Sound 모듈 구현

**수정/추가한 파일**

- `include/sound.h`
- `src/sensors/sound.c`
- `tests/test_sound.c`

**구현한 기능**

- DE1-SoC Audio Core의 MMIO 레지스터를 이용한 오디오 입력 인터페이스 구현
- Audio-in FIFO 초기화 및 입력 데이터 읽기 기능 작성
- 좌·우 채널의 PCM 오디오 샘플을 읽어 진폭 계산
- 입력된 샘플 중 최대 진폭(Peak Amplitude)을 소리 크기 지표로 사용
- 여러 번의 FIFO 읽기에서 최대 진폭을 누적하고, 측정값 반환 후 초기화
- 잘못된 출력 포인터 및 입력 데이터가 없는 상황 처리

**주요 변경 사항**

- Audio-in 레지스터 접근을 `AUDIO_MMIO_READ`, `AUDIO_MMIO_WRITE` 매크로로 분리
- 실제 하드웨어 없이 동작을 검증할 수 있도록 Mock MMIO 테스트 구성
- 원본 오디오 데이터를 저장하지 않고 16비트 진폭 값만 추출하여 저장 공간 절약
- Audio FIFO 오버플로를 방지하기 위해 입력 처리 함수와 측정값 조회 함수를 분리

**주요 함수**

| 함수 | 기능 |
|---|---|
| `sound_init()` | Audio-in FIFO 초기화 및 내부 상태 초기화 |
| `sound_update()` | FIFO 데이터를 읽어 최대 진폭 누적 |
| `sound_read()` | 누적된 최대 진폭 반환 및 측정 상태 초기화 |

## 5. 발생한 문제 및 해결

### 문제 1. 실제 Audio 하드웨어 없이 소리 입력 로직 검증 필요

- **문제:** Mac 환경에서 DE1-SoC Audio-in FIFO에 직접 접근할 수 없음
- **원인:** 하드웨어 MMIO 레지스터와 오디오 장치가 연결되지 않은 상태
- **시도한 해결 방법:** Audio MMIO 접근을 Mock 함수로 대체하고 가상의 PCM 데이터를 입력하여 테스트
- **결과:** FIFO 초기화, 진폭 계산, Peak 누적 및 초기화 등 7개 테스트 통과

### 문제 2. 센서별 데이터 수집 방식 차이

- **문제:** 진동·조도 센서는 ADC 기반으로 수집하지만 소리 센서는 Audio FIFO를 통해 연속적으로 데이터가 입력됨
- **원인:** 센서별 하드웨어 입력 인터페이스 및 데이터 처리 주기가 다름
- **시도한 해결 방법:** `sensor_manager_poll()`과 `sensor_manager_sample()`을 분리하여 Audio FIFO 처리와 10ms 센서 샘플링을 별도로 수행
- **결과:** 센서별 입력 방식을 유지하면서 공통 `SensorSample` 구조체로 통합하는 로직 구현

### 문제 3. Ring Buffer 테스트 실행 파일 누락

- **문제:** 전체 단위 테스트 재실행 과정에서 `build/test_ring_buffer` 파일을 찾지 못함
- **원인:** 해당 테스트 실행 파일이 현재 빌드 디렉터리에 존재하지 않음
- **시도한 해결 방법:** Clang으로 `test_ring_buffer.c`와 `ring_buffer.c`를 다시 컴파일
- **결과:** 실행 파일 생성 및 6개 단위 테스트 모두 통과
