### 작업 1. Sensor Manager와 이벤트 감지 모듈 통합

**관련 파일**

- 통합 테스트용 `main.c`
- `event_detector.c`
- `event_classifier.c`
- `sensor_manager.c`

**통합한 기능**

- Timer 기반 10ms 센서 샘플링
- `SensorSample` 구조체 생성
- `event_detect()`를 이용한 이벤트 종류 판단
- 이벤트 발생 시 `event_classify()`를 통한 분류
- 이벤트 플래그에 따른 LED/HEX 및 알람 처리 호출
- JTAG UART를 이용한 이벤트 발생 로그 출력

**주요 처리 흐름**

```text
Timer 10ms Tick
      ↓
sensor_manager_sample()
      ↓
event_detect(&sample)
      ↓
Event Flags 생성
      ↓
LED/HEX 표시
      ↓
event_classify(flags)
      ↓
alarm_start(...)
```

이벤트가 발생하지 않은 경우에는 센서 모니터링을 계속 수행하도록 구성하였다.

### 작업 2. LED/HEX 및 KEY 입력 통합

**통합한 기능**

- `key_init()`을 통한 KEY 입력 모듈 초기화
- `key_take_events()`를 이용한 버튼 이벤트 수신
- `led_hex_init()`을 통한 출력 장치 초기화
- 이벤트 발생 시 `led_hex_show(flags)` 호출
- 메인 루프에서 `led_hex_update(now_ms)` 호출
- KEY0 입력 시 알람 중지
- KEY1 입력 시 알람 중지 및 LED/HEX 초기화

**이벤트 플래그 정의**

| Flags | 이벤트 |
|---|---|
| 0 | 이벤트 없음 |
| 1 | 진동 |
| 2 | 소음 |
| 3 | 진동 + 소음 |
| 4 | 조도 |
| 5 | 진동 + 조도 |
| 6 | 소음 + 조도 |
| 7 | 진동 + 소음 + 조도 |

**출력 장치 매핑**

- LEDR0: 진동
- LEDR1: 소음
- LEDR2: 조도
- HEX1: 진동
- HEX2: 소음
- HEX3: 조도
- HEX4: 복합 이벤트

실제 통합 코드에서 해당 출력 함수들을 호출하도록 연결하였으며, 이벤트별 표시 동작 전체는 추가 검증이 필요하다.

## 5. 발생한 문제 및 원인 분석

### 문제 1. FPGA 전원 재인가 이후 JTAG 관련 오류

**발생한 현상**

기존에 정상 실행되던 프로젝트가 보드 전원을 껐다 켠 뒤 정상적으로 Load되지 않는 문제가 발생하였다.

**오류 메시지**

```text
Verify failed between address 0x200 and 0xD35B

Could not query JTAG Instance IDs.
Please ensure the FPGA has been configured
using the correct .sof file.
```

**진행한 확인 작업**

- USB-Blaster 및 전원 케이블 재연결
- FPGA Monitor Program 재시작
- 프로젝트 Connection / System / Memory Settings 확인
- FPGA Monitor Program을 이용한 `.sof` 다운로드
- 기존 센서 테스트 프로젝트 및 다른 프로젝트 실행 시도
- LEDR 직접 제어 프로그램을 통한 Nios II 실행 확인

**결과**

- `.sof` 다운로드 성공
- Nios II 프로세서 접근 및 LEDR 제어 성공
- 이후 통합 프로그램 Load 및 실행 성공

**판단**

전원 재인가 이후 FPGA/JTAG 또는 메모리 접근 상태와 관련된 일시적 문제가 발생한 것으로 추정되지만, 정확한 원인은 확인하지 못하였다.

### 문제 2. 진동 이벤트 감지 실패

**발생한 현상**

진동 센서의 ADC 측정값은 크게 변하지만 이벤트 플래그가 생성되지 않음.

**관련 코드**

```c
sample->vibration > SHOCK_THRESHOLD
```

**원인 분석**

실제 센서 측정값은 자극에 따라 크게 감소하는 양상을 보였으나, 이벤트 감지 함수는 측정값이 임계값보다 큰 경우만 판단하고 있다.

따라서 실제 센서 출력 특성과 임계값 비교 방식이 맞지 않을 가능성이 있다.

**개선 방향**

- `SHOCK_THRESHOLD` 값 확인
- 센서 출력 특성에 따른 임계값 조정
- 기준값 대비 변화량 기반 감지 방식 검토

**상태:** 원인 추정 완료, 수정 및 재검증 필요

### 문제 3. 조도 이벤트 감지 지연

**발생한 현상**

밝기를 변화시키면 조도값은 즉시 변하지만 이벤트는 일정 시간이 지난 후 발생함.

**원인 분석**

- `EVENT_CONFIRM_SAMPLES` 연속 감지 조건
- `LIGHT_CHANGE_THRESHOLD`
- `s_light_base` 갱신 방식

위 요소가 감지 지연에 영향을 줄 가능성이 있다.

**개선 방향**

실제 10ms 샘플별 변화량과 이벤트 확정 시점을 비교하고, 임계값 및 기준값 갱신 정책을 검토한다.

**상태:** 이벤트 발생 확인, 감지 지연 원인 추가 분석 필요

### 문제 4. 복합 이벤트 감지 실패

**발생한 현상**

소음과 조도를 동시에 자극했지만 `Flags:6` 대신 `Flags:2`만 발생함.

**원인 분석**

현재 `detect_confirmed()`는 이벤트가 새롭게 확정되는 순간에만 `true`를 반환한다.

따라서 소음과 조도 이벤트가 서로 다른 샘플에서 확정되면 동일한 `event_detect()` 호출에서 두 플래그가 함께 생성되지 않는다.

**개선 방향**

- 센서별 이벤트 활성 상태 관리
- 일정 시간 범위 내 이벤트 조합
- 복합 이벤트 확정 기준 정의

**상태:** 구조적 원인 분석, 로직 수정 필요

### 문제 5. HEX 소음 경고 표시 유지

**발생한 현상**

소음 이벤트 발생 후 소음값이 정상으로 돌아와도 HEX에 소음 표시가 유지됨.

**원인 분석**

`main.c`에서 이벤트 발생 시 `led_hex_show(flags)`를 호출하지만, 이벤트가 종료되었다고 해서 자동으로 `led_hex_clear()`를 호출하지 않는다.

**추가 확인 사항**

- `led_hex.c`의 표시 유지 정책
- KEY1 수동 초기화 방식이 의도된 설계인지
- 이벤트 종료 시 자동 초기화가 필요한지

**상태:** 표시 정책 확인 필요
