# 개발일지 — 2026-11-19

## 1. 개발 개요

- **프로젝트명:** 다중 센서 기반 실시간 이벤트 감지 및 데이터 블랙박스 시스템
- **개발 환경:** DE1-SoC, Nios II, C, JTAG UART
- **개발 내용:** 센서 입력 및 이벤트 감지 모듈 통합, Ring Buffer·Event Record·Event History 구현 및 테스트, 센서 임계값 조정, 콘솔 출력 개선

---

## 2. 주요 개발 내용

### 2.1. 센서 데이터 수집 및 초기 기준값 설정

- 진동·조도·소음 센서 데이터를 `SensorSample` 구조체로 통합 관리
- Timer Interrupt는 1ms 주기로 발생하며, 센서 데이터는 10ms 간격으로 수집
- 최초 5초 동안 센서 데이터를 수집하고 평균값(Baseline) 계산
- 계산된 Baseline을 Event Detector와 Risk Level 모듈에 전달
- Calibration 및 LED 준비 단계에서도 Ring Buffer에 센서 데이터 지속 저장
- JTAG UART를 통해 센서 측정값과 초기 기준값 출력

### 2.2. 이벤트 감지 및 임계값 조정

- SHOCK, SOUND, LIGHT 단일 이벤트 감지 기능 통합
- 초기 Baseline과 현재 측정값의 변화량을 기준으로 이벤트 감지
- 조도 센서에서 LIGHT 이벤트가 반복 발생하는 현상 확인
- `LIGHT_CHANGE_THRESHOLD` 조정 및 LIGHT 재감지 잠금 해제 조건 개선
- 정상 범위가 일정 시간 유지되어야 재감지를 허용하는 방식 적용
- SOUND Baseline 변동 및 센서별 임계값 설정 방식 검토
- 단일 이벤트 감지는 확인했으나 복합 이벤트 감지는 정상 동작하지 않는 문제 확인

### 2.3. Ring Buffer 구현 및 검증

- 최근 5초간 센서 데이터를 유지하는 Circular Buffer 구현
- 10ms 샘플링 기준 총 500개 센서 샘플 저장
- 버퍼가 가득 차면 오래된 데이터를 덮어쓰는 방식 적용
- 이벤트 발생 시 이전 500개 데이터를 Event Record로 복사
- 실제 보드에서 이벤트 발생 이전 5초 구간의 센서값 및 타임스탬프 출력 확인

### 2.4. Event Record 구현 및 검증

- 이벤트 이전 500개와 이후 500개로 구성된 총 1,000개 센서 데이터 저장 구조 구현
- 가장 최근 이벤트의 Record 1개만 유지
- 새로운 이벤트 발생 시 기존 Record 전체를 교체
- 이벤트 발생 즉시 BEFORE 대표 샘플 5개 출력
- AFTER 데이터 수집 중 100개 샘플마다 대표값 출력
- 실제 보드에서 `Pre:500 | Post:500 | Total:1000` 및 저장 완료 메시지 확인

### 2.5. Event History 구현 및 검증

- 이벤트 발생 시간과 Flags를 최대 10건까지 저장
- Event Record와 독립적으로 History 유지
- 새 이벤트 발생 시 현재 History 개수 `(N/10)` 출력
- 10초마다 최근 History 10건 자동 출력
- History 출력 순서를 오래된 이벤트에서 최근 이벤트 순서(시간 오름차순)로 변경
- 단일 이벤트 저장 및 순환 관리 확인
- 복합 이벤트 Flags 저장은 실제 복합 감지가 발생하지 않아 검증되지 않음

### 2.6. JTAG UART 콘솔 출력 개선

- `[SENSOR]`: 약 1초마다 실시간 센서 측정값 출력
- `[EVENT]`: 이벤트 발생 시간 및 Flags 즉시 출력
- `[HISTORY]`: 이벤트 발생 시 저장 개수 출력
- `[RECORD] BEFORE`: 이전 500개 중 대표 샘플 5개 출력
- `[RECORD] AFTER`: 이후 500개 수집 중 대표 샘플 5개 출력
- `[RECORD] SAVED`: 총 1,000개 저장 완료 시 출력
- `EVENT HISTORY`: 10초마다 최근 이벤트 10건 출력

### 2.7. 실제 보드 통합 테스트

- Sensor Manager, Timer/Interrupt, Event Detector, Ring Buffer, Event Record, Event History, LED/HEX, KEY 모듈 통합
- SHOCK·SOUND·LIGHT 단일 이벤트 감지 확인
- Event Record 이전·이후 샘플 수집 및 저장 완료 확인
- Event History 저장 및 출력 확인
- KEY1 입력 시 LED/HEX 초기화 확인
- 복합 이벤트 감지는 정상 동작하지 않음
- Audio-out 코드 통합 상태이나 실제 스피커 출력은 테스트하지 않음

## 4. 발생한 문제 및 해결 과정

**문제 1. LIGHT 이벤트 반복 발생**

- **원인:** 낮은 조도 변화량 임계값 및 빠른 재감지 잠금 해제
- **해결:** 조도 임계값 조정, 안정 시간 기반 재감지 조건 적용
- **결과:** LIGHT 반복 발생 빈도 감소

**문제 2. Event Record가 수집 도중 반복 초기화됨**

- **원인:** 신규 이벤트 발생 시 기존 Record를 교체하는 구조에서 이벤트가 빈번하게 발생
- **해결:** 이벤트 반복 감지 감소 및 저장 과정 확인
- **결과:** 총 1,000개 저장 완료 확인

**문제 3. 복합 이벤트 감지 실패**

- **현상:** SHOCK, SOUND, LIGHT는 개별적으로 감지되지만, 두 가지 이상이 결합된 복합 이벤트 Flags는 발생하지 않음
- **원인 분석:** 현재 `event_detect()`는 각 센서에서 새롭게 확정된 이벤트 Flags를 동일한 함수 호출 시점에 OR 연산하여 반환하는 구조임. 센서마다 이벤트 확정 시점, 연속 감지 조건, 쿨다운 및 잠금 해제 조건이 달라 복합 이벤트가 발생하기 어려울 가능성이 있음
- **해결 계획:** 일정 시간 내 발생한 센서별 이벤트를 복합 이벤트로 판단하는 방식 검토
- **현재 상태:** 미해결, 추가 구현 및 테스트 필요

**문제 4. JTAG UART 출력 문자열 누락**

- **현상:** 로그 출력 도중 일부 문자가 잘리는 현상 발생
- **원인 추정:** UART 출력 함수의 전송 대기 타임아웃
- **대응:** 대표 샘플 중심으로 콘솔 출력량 감소
- **향후 계획:** UART 출력 안정화 및 샘플링 주기 영향 점검

**문제 5. 초기 Baseline 변동**

- **원인 가능성:** 초기 측정 구간 중 외부 자극 및 일시적인 센서값 변화
- **대응:** 초기 5초 평균 유지 및 센서별 임계값 검토
- **향후 계획:** Baseline 안정화 및 감지 기준 보정

## 6. 개발 결과 요약

실제 DE1-SoC 보드에서 센서 데이터 수집, SHOCK·SOUND·LIGHT 단일 이벤트 감지, Ring Buffer 이전 500개 데이터 확보, Event Record의 총 1,000개 저장 완료 및 Event History 관리 기능을 확인하였다.

다만 복합 이벤트 감지는 정상 동작하지 않아 추가적인 감지 로직 개선이 필요하다. 향후 복합 이벤트 처리, JTAG UART 출력 안정화, VGA 화면 출력 및 실제 스피커 테스트를 진행할 예정이다.
