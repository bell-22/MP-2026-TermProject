### 작업 2. LEDR 기반 실행 단계 디버깅

**대상 파일**

- `tests/test_sensor_console.c`

**작업 내용**

JTAG UART 출력이 정상적으로 표시되지 않는 상황에서 LEDR를 실행 위치 표시 수단으로 사용하였다.

**디버깅 코드**

```c
#define LEDR (*(volatile unsigned int *)0xFF200000U)
```

**LED 상태별 확인 내용**

| LED 값 | 확인 단계 |
|---|---|
| `0x001` | `main()` 진입 |
| `0x003` | Sensor Manager 초기화 |
| `0x007` | Timer/Interrupt 설정 |
| `0x00F` | 샘플링 Tick 처리 |
| `0x01F` | `sensor_manager_sample()` 실행 성공 |

LED 표시를 통해 프로그램이 센서 샘플 생성 단계까지 진행된다는 것을 확인하였다.

### 작업 3. JTAG UART 출력 문제 해결

**발생한 문제**

- 단순 Hello World 프로그램의 `printf()` 출력은 정상 동작
- 센서 통합 프로그램에서는 `printf()`가 정상적으로 출력되지 않는 현상 발생
- 센서 수집 로직 자체는 LED 디버깅으로 실행 확인

**적용한 방법**

JTAG UART의 MMIO 레지스터에 직접 접근하는 출력 함수를 작성하여 기존 `printf()` 출력 방식을 대체하였다.

```c
#define JTAG_UART_BASE 0xFF201000U
```

- JTAG UART Data Register에 문자 직접 기록
- Control Register의 송신 FIFO 여유 공간 확인
- 문자열 출력 함수 `uart_print()` 구현
- `snprintf()`로 센서 측정값을 문자열로 변환한 후 `uart_print()` 호출

**결과**

- JTAG UART Terminal에 초기화 메시지 출력 성공
- 진동·조도·소리 측정값 출력 성공
- 기존 `printf()` 출력 오류의 근본 원인은 확인하지 못했지만, 직접 MMIO 출력 방식으로 테스트 진행 가능

### 작업 4. 실제 센서 통합 테스트

**테스트 구성**

```text
Timer IRQ
    ↓
10ms Sample Tick
    ↓
sensor_manager_poll()
    ↓
sensor_manager_sample()
    ↓
SensorSample 생성
    ↓
JTAG UART 출력
```

**검증 내용**

- Timer 기반 샘플링 루프 동작
- 진동 센서 ADC 값 수집
- 조도 센서 ADC 값 수집
- Audio-in 기반 소리 크기 데이터 수집
- 각 센서에 자극을 주었을 때 측정값 변화 확인
- 약 1초 간격으로 통합 센서 데이터 출력

**출력 형식**

```text
Time:1000 ms | Vibration:... | Light:... | Sound:...
```

센서별 측정값이 실제 보드에서 출력되고, 입력 변화가 반영되는 것을 확인하였다.

## 5. 발생한 문제 및 해결

### 문제 1. Nios II 컴파일 과정의 소스 및 헤더 구성 문제

- **문제:** 프로젝트에 등록된 파일과 헤더 경로 문제로 컴파일 오류 발생
- **원인:** 프로젝트의 Source Files 등록 및 Include 경로 구성 불일치
- **해결:** 필요한 `.c` 파일만 빌드 대상으로 등록하고 헤더 참조 경로 수정
- **결과:** 센서 테스트 프로그램 컴파일 성공

### 문제 2. 통합 프로그램의 `printf()` 출력 실패

- **문제:** 실행 단계는 진행되지만 터미널 출력이 표시되지 않음
- **확인:** LEDR를 통해 샘플 생성 단계까지 실행되는 것을 확인
- **해결:** JTAG UART MMIO에 직접 접근하는 `uart_print()` 구현
- **결과:** 센서 측정값 출력 성공
- **미해결 사항:** 기존 `printf()` 출력 실패 원인

### 문제 3. JTAG UART 출력 중 정지 가능성

- **문제:** 일부 실행에서 제한된 메시지만 출력된 뒤 추가 출력이 나타나지 않는 현상 관찰
- **가능 원인:** UART 송신 FIFO 대기 루프 또는 다른 실행 경로의 정지
- **개선 방향:** 송신 FIFO 대기에 타임아웃을 추가하여 무한 대기를 방지
- **결과:** 해당 현상의 근본 원인은 추가 검증 필요
