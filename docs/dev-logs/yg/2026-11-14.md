| 상태 | 의미 |
|---|---|
| `STATE_MONITORING` | 센서 데이터 감시 및 이벤트 대기 |

주요 API는 다음과 같다.

```c
void system_state_init(void);
SystemState system_state_get(void);
void system_state_set(SystemState next);
```

**구현 내용**

- 시스템 초기 상태를 `STATE_MONITORING`으로 설정
- `MONITORING → RECORDING` 상태 전환 처리
- `RECORDING → SAVED` 상태 전환 처리
- 기록 취소 또는 초기화에 따른 `MONITORING` 복귀 처리
- 잘못된 상태값 및 허용되지 않은 상태 전환 방지
- 동일 상태로의 중복 전환 처리 방지

**확인 결과**

- 정상적인 상태 전환 확인
- 잘못된 상태 전환 차단 확인
- 초기화 후 `MONITORING` 복귀 확인

### 작업 3. 이벤트 종류별 Audio 경고 패턴 구현

**작업 내용**

이벤트 종류에 따라 서로 다른 경고음을 출력하는 제어 로직을 구현하였다.

| 이벤트 | 경고 패턴 |
|---|---|
| SHOCK | 800Hz 경고음 1회 |
| SOUND | 800Hz 경고음 2회 |
| LIGHT | 800Hz 경고음 3회 |
| MULTIPLE | 600Hz → 1200Hz 연속 출력 |

**주요 API**

```c

void alarm_start(uint8_t event_code);
void alarm_update(uint32_t timestamp_ms);
void alarm_stop(void);
bool alarm_is_active(void);
```

- 경고음 출력 및 무음 구간 구분

**작업 내용**

센서 데이터의 임계값 초과 여부, 이상 상태의 지속시간 및 복합 센서 감지 여부를 이용하여 위험 단계를 판단하는 모듈을 구현하였다.

| 위험 단계 | 판정 기준 |

| DANGER | 복합 이상, 임계값 2배 이상, 또는 이상 상태 1초 이상 지속 |

위 기준은 실제 센서 보정 전의 초기 테스트 기준이다.

**주요 API**

```c

RiskLevel risk_level_update(
    const SensorSample *sample
);
```

**구현 내용**

- `SensorSample`을 이용한 위험 단계 판단
- 충격·소음·조도 변화의 임계값 비교
- 두 개 이상 센서의 동시 이상 상태 판단
- 임계값의 2배 이상 측정 시 위험 단계 판정
- 이상 상태가 1초 이상 지속되는지 확인
- 정상 상태 복귀 시 위험 단계 초기화
- 샘플 시간 간격을 이용한 연속성 관리

**문제**

**결과**

- 최신 이벤트 1건 자동 교체 저장 정책 협의
