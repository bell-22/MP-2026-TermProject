**진행 내용**

**통합 처리 흐름**

```text
Timer IRQ0 (1ms)
    ↓
10ms Sampling Tick
    ↓
sensor_manager_poll()
    ↓
sensor_manager_sample()
    ↓
SensorSample 생성
    ↓
event_detect()
    ↓
Event Flags 반환
    ↓
led_hex_show()
    ↓
JTAG UART 이벤트 로그 출력
```

**주요 작업**

- 센서 데이터 수집과 이벤트 감지 연결

- 이벤트 종류와 발생시간 로그 출력
- `led_hex_update()`를 메인 루프에서 주기적으로 호출
- KEY 입력 이벤트 확인 및 처리 코드 연결
- Audio-in 센서 수집 기능 유지

### 작업 2. 실제 센서 측정 및 이벤트 로그 분석

**실험 환경**

- DE1-SoC 보드
- FPGA Monitor Program
- JTAG UART Terminal
- 진동·조도·소음 센서

**확인 내용**

실제 센서에 자극을 주면서 측정값과 이벤트 발생 여부를 확인하였다.

관찰된 데이터 예시는 다음과 같다.

```text
Time:1000 ms | Vibration:1216 | Light:188 | Sound:55
Time:2000 ms | Vibration:1216 | Light:179 | Sound:45

[EVENT] Time:2450 ms | Flags:2

Time:5000 ms | Vibration:1216 | Light:184 | Sound:1560
Time:9000 ms | Vibration:288  | Light:183 | Sound:60
```

**실험에서 확인된 내용**

- 세 센서의 측정값 출력
- 실제 진동 자극에 따른 ADC 값 변화
- 조도 변화에 따른 센서값 변화
- 소음 입력에 따른 음량 특징값 증가
- 소음 이벤트 발생 및 플래그 출력

**발견한 문제**

- 진동값이 크게 변해도 기존 절대 임계값으로는 이벤트를 감지하기 어려움
- 조도 변화량이 기존 설정 임계값에 도달하지 못하는 경우 존재
- 소음 이벤트가 반복적으로 발생하는 현상 확인
- 복합 이벤트는 해당 실험에서 정상 발생을 확인하지 못함

### 작업 3. 센서 이벤트 임계값 개선

**대상 파일**

- `include/system_config.h`
- `include/event_detector.h`
- `src/event/event_detector.c`
- `include/risk_level.h`
- `src/event/risk_level.c`
- `src/main.c`

**문제 분석**

초기 이벤트 감지 방식은 실제 센서 특성을 충분히 반영하지 못하였다.

진동 센서는 충격 시 측정값이 감소할 수도 있어 단순히 큰 값인지 검사하는 방식만으로는 감지가 어려웠다.

조도 센서도 초기 상태와 현재 상태의 차이를 반영하는 방식이 더 적합하다고 판단하였다.

**개선 방향**

프로그램 시작 후 초기 구간에서 실제 측정값을 수집하고, 각 센서의 평균값을 기준으로 현재 변화량을 계산하도록 설계를 수정하였다.

**당일 작성한 초기 변경 설정**

| 항목 | 변경 내용 |
|---|---|
| 초기 기준값 측정 | 1초 평균 측정 방식 |
| 진동 | 초기 평균 대비 변화량 400 |
| 조도 | 초기 평균 대비 변화량 50 |
| 소음 | 초기 평균 대비 변화량 900 |
| 이벤트 확정 | 연속 2회 |
| 이벤트 쿨다운 | 1초 |

**구현 내용**

- 센서별 초기 평균값 계산 변수 추가
- 진동·조도·소음 평균값 저장 API 수정
- 현재 센서값과 초기 평균값의 절댓값 차이 계산
- 이벤트 감지 및 위험도 모듈의 기준값 통일
- 초기 평균 측정 중 이벤트 감지 비활성화

**진행 결과**

평균값 기반 감지 구조를 코드에 반영하는 작업을 진행하였다. 변경된 임계값의 실제 검출 성능은 재실험이 필요한 상태였다.

### 작업 4. 소음 이벤트 반복 감지 오류 분석 및 개선

**대상 파일**

- `src/event/event_detector.c`
- `include/system_config.h`

**발생한 문제**

소음 이벤트가 발생한 후 약 1초 간격으로 동일한 이벤트가 반복되는 현상을 확인하였다.

**원인 분석**

- 소음값이 잠시 임계값 아래로 내려가면 기존 래치가 해제됨
- 이후 다시 임계값을 넘으면 새로운 이벤트로 판정 가능
- 1초 쿨다운만으로는 반복 감지를 충분히 방지하지 못함

**개선 내용**

- 소음 이벤트 발생 후 래치 상태 유지
- 소음 변화량이 복귀 기준 이하인 상태가 일정 시간 유지되어야 재감지 허용
- 정상 복귀 확인 시간을 300ms로 설정
- 기존 1초 쿨다운 유지
- 소음 이벤트 확정과 재감지 허용 조건을 별도 함수로 관리

**초기 설정값**

```c
#define SOUND_CHANGE_THRESHOLD 900U
#define SOUND_RESET_CHANGE_THRESHOLD 400U
#define SOUND_RESET_DURATION_MS 300U
```

**결과**

소음값이 일시적으로 낮아지는 경우 발생할 수 있는 중복 이벤트를 방지하도록 로직을 수정하였다.

실제 보드에서의 반복 감지 감소 효과는 추가 확인이 필요하였다.

- 기존 이벤트 표시 기능과 준비 알림 기능의 충돌 방지

**결과**

초기 센서 평균 측정 완료 여부를 LED로 확인할 수 있는 코드 구조를 작성하였다.

## 5. 발생한 문제 및 해결

### 문제 1. 진동 센서 감지 실패

- **문제:** 진동 센서값이 크게 변했음에도 충격 이벤트가 발생하지 않는 현상
- **원인:** 기존 절대 임계값이 실제 센서의 값 변화 방향과 맞지 않음
- **해결 방향:** 초기 평균값과 현재값의 절댓값 차이 사용
- **결과:** 변화량 기반 감지 코드 수정 진행
- **추가 검증:** 보드에서 충격 이벤트 발생 확인 필요

### 문제 2. 조도 센서 감지 실패

- **문제:** 밝기 변화가 있었으나 이벤트가 감지되지 않는 경우 발생
- **원인:** 실제 변화량에 비해 높은 기존 임계값
- **해결 방향:** 초기 평균값 대비 변화량을 기준으로 감지
- **결과:** 조도 임계값 보정 및 기준값 계산 구조 수정
- **추가 검증:** 다양한 밝기 조건에서 동작 확인 필요

### 문제 3. 소음 이벤트 반복 발생

- **문제:** 하나의 소음 상황에서 이벤트가 반복적으로 발생
- **원인:** 순간적인 소음 감소로 재감지 잠금 해제 가능
- **해결:** 300ms 정상 복귀 확인 조건 및 기존 쿨다운 유지
- **결과:** 반복 감지 방지 로직 개선
- **추가 검증:** 장시간 소음 실험 필요

### 문제 4. 스피커 경고음 출력 미확인

- **문제:** 이벤트 감지와 경고음 요청 코드가 있어도 실제 소리가 들리는지 확인되지 않음
- **가능 원인:** Audio-out 드라이버, CODEC 설정 또는 스피커 연결
- **진행 내용:** 경고 패턴과 실제 출력 드라이버를 구분하여 점검 계획 수립
- **결과:** 하드웨어 출력 확인 필요
