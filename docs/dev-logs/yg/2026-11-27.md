### 작업 2. KEY0~KEY3 입력 기능 확장

**작업 대상**

- `include/key_switch.h`
- `src/input/key_switch.c`
- `src/system/interrupt.c`
- `src/main.c`

**작업 내용**

기존 프로그램에서는 KEY0과 KEY1만 사용하고 있었으나, VGA 화면 전환을 위해 KEY2와 KEY3 입력 기능을 추가하였다.

**최종 KEY 동작**

| KEY | 기능 |
|---|---|
| KEY0 | 경고음만 중지 |
| KEY1 | 경고음 중지 및 LED OFF, HEX 00 |
| KEY2 | VGA 실시간 모니터링 화면 |
| KEY3 | VGA 과거 이벤트 화면 |

KEY1을 눌러도 Ring Buffer, Event History, Event Record에 저장된 데이터는 삭제하지 않도록 기존 동작을 유지하였다.

**KEY 이벤트 정의 추가**

```c
#define KEY_EVENT_STOP         (1U << 0)
#define KEY_EVENT_CLEAR        (1U << 1)
#define KEY_EVENT_VIEW_LIVE    (1U << 2)
#define KEY_EVENT_VIEW_HISTORY (1U << 3)
```

`key_switch.c`에서는 기존 KEY0, KEY1에만 적용하던 디바운싱을 KEY0~KEY3으로 확장하였다.

각 버튼의 마지막 입력 시간을 별도로 저장하여 50ms 디바운싱을 독립적으로 적용하였다.

**인터럽트 사용 범위 변경**

기존 코드:

```c
#define KEY_USED_MASK 0x3U
```

수정 코드:

```c
#define KEY_USED_MASK 0xFU
```

이를 통해 KEY0~KEY3의 Edge Capture 인터럽트를 모두 허용하도록 수정하였다.

**개선 결과**

기존 KEY0, KEY1 기능을 유지하면서 KEY2와 KEY3 입력 이벤트를 메인 루프에 전달할 수 있도록 구현하였다.

다만 KEY2와 KEY3의 실제 화면 전환 동작은 VGA 모니터 연결 후 검증할 예정이다.

**작업 대상**

- `include/vga.h`

- `include/event_history.h`
- `src/storage/event_history.c`

**작업 내용**

KEY3 입력 시 저장된 최근 이벤트를 확인할 수 있도록 VGA 화면 2를 구현하였다.

**화면 구성**

- 상단 제목: `LAST EVENT`
- 우측 상태 표시: `SAVED`
- 이벤트 목록: `NO. / TIME / TYPE / DELTA`
- 최근 이벤트 최대 10개 표시

이벤트 이력은 `event_history_get()`을 이용하여 최신 이벤트부터 역순으로 표시하도록 구현하였다.

**History 자동 갱신 기능**

기존 Event History 저장 기능과 VGA 화면 갱신 기능을 분리하였다.

1. 실제 새로운 이벤트가 감지되면 History에 저장한다.
2. VGA History 화면을 열면 현재 저장된 이벤트를 조회한다.
3. History 화면을 유지하는 동안 1초마다 최신 저장 내용을 다시 조회한다.
4. KEY3을 다시 누르면 History 표시를 새로고침한다.
5. 화면 갱신 과정에서는 새로운 이벤트를 중복 저장하지 않는다.

History의 저장 개수는 기존과 동일하게 최대 10개를 유지하도록 하였다.

**개선 결과**

새로운 이벤트가 발생했을 때 VGA 화면에 최신 History 정보가 반영될 수 있도록 구현하였다.

기존 저장 데이터는 유지하고 표시 정보만 갱신하는 방식을 적용하였다.

### 작업 5. Event History DELTA 저장 기능 추가

**작업 대상**

- `include/event_history.h`
- `src/storage/event_history.c`
- `src/main.c`

**작업 내용**

기존 Event History에는 이벤트 발생 시각과 이벤트 종류만 저장되어 있었다.

VGA History 화면에서 이벤트별 변화량을 표시하기 위해 `delta` 필드를 추가하였다.

**수정된 이벤트 구조체**

```c
typedef struct
{
    uint32_t timestamp_ms;
    uint8_t event_flags;
    uint16_t delta;
} EventHistoryEntry;
```

**추가 함수**

```c
bool event_history_push_with_delta(
    uint32_t timestamp_ms,
    uint8_t flags,
    uint16_t delta
);

bool event_history_upgrade_latest_with_delta(
    uint32_t timestamp_ms,
    uint8_t new_flags,
    uint16_t delta
);
```

**DELTA 계산 방식**

초기 5초 동안 측정한 센서 평균값을 기준으로 이벤트 발생 당시 센서값의 절댓값 변화량을 계산하였다.

단일 이벤트는 해당 센서의 변화량을 저장하고, 복합 이벤트는 이벤트에 포함된 센서들 중 가장 큰 변화량을 저장하도록 하였다.

기존 이벤트가 복합 이벤트로 확장되는 경우에는 새로운 History 항목을 만들지 않고 기존 항목의 Flags와 DELTA를 갱신하도록 하였다.

**개선 결과**

Event History의 최대 10개 순환 저장 기능을 유지하면서 각 이벤트의 변화량을 함께 저장할 수 있도록 수정하였다.

기존 `event_history_push()` 및 `event_history_upgrade_latest()` 함수도 유지하여 기존 인터페이스와의 호환성을 보존하였다.

### 작업 7. VGA 함수 링크 오류 해결

**발생한 문제**

VGA 코드를 `main.c`에 연결한 후 프로그램 빌드 과정에서 다음과 같은 링커 오류가 발생하였다.

```text

undefined reference to `vga_set_screen'
undefined reference to `vga_set_baseline'
undefined reference to `vga_update'
collect2.exe: error: ld returned 1 exit status
```

**원인 분석**

`vga.h`는 정상적으로 포함되어 있어 함수 선언은 인식되었으나, Makefile의 소스 파일 목록에 `src/display/vga.c`가 포함되지 않아 VGA 함수의 실제 구현이 링크되지 않는 문제였다.

**해결 방법**

Makefile의 `SRCS` 항목에 VGA 소스 파일을 추가하도록 수정하였다.

```makefile
src/display/vga.c
```

**해결 결과**

이후 실제 보드 실행 로그에서 VGA 초기화 메시지를 확인하였다.

```text
[INIT] VGA OK
```

따라서 VGA 함수 링크 오류가 해결되고 통합 프로그램이 실행 단계까지 진행되었음을 확인하였다.

단, Makefile은 Intel FPGA Monitor Program이 자동 생성하므로 프로젝트 재생성 시 VGA 소스 파일 포함 여부를 다시 확인해야 한다.

로그 일부가 누락되었지만 최신 이벤트가 추가되면서 저장 개수가 최대 10개로 유지되는 것을 확인하였다.

**KEY 동작 확인**

```text
[KEY0] Alarm stopped
[KEY1] Alarm and display cleared
```

KEY0의 경고음 중지와 KEY1의 경고 및 LED/HEX 초기화 동작을 확인하였다.

KEY1 이후에도 이벤트 감지가 계속되고 새로운 History가 저장되는 것을 확인하여 저장 데이터 보존 정책이 유지되고 있음을 확인하였다.

## 5. 발생한 문제 및 해결

### 문제 1. VGA 함수 undefined reference 오류

**문제**

VGA 모듈 작성 이후 프로그램 빌드 중 `vga_init()`, `vga_set_screen()`, `vga_set_baseline()`, `vga_update()` 함수의 참조 오류가 발생하였다.

**원인 분석**

Makefile의 `SRCS`에 `vga.c`가 포함되어 있지 않아 컴파일된 VGA 함수 구현이 최종 실행 파일에 링크되지 않았다.

**해결**

- Makefile 소스 목록 확인
- `src/display/vga.c` 추가
- VGA 소스 파일의 빌드 대상 포함
- 프로그램 재빌드 및 실행

**결과**

실행 로그에서 `[INIT] VGA OK` 메시지를 확인하였으며 통합 프로그램이 실행되었다.

### 문제 2. Event History DELTA 정보 부재

**문제**

기존 History 구조체에는 이벤트 발생 시각과 Flags만 존재하여 VGA History 화면에 센서 변화량을 표시할 수 없었다.

**원인 분석**

기존 Event History 모듈에는 DELTA 저장 필드와 관련 함수가 구현되어 있지 않았다.

**해결**

- `EventHistoryEntry`에 `delta` 필드 추가
- `event_delta()` 계산 함수 추가
- `event_history_push_with_delta()` 구현
- `event_history_upgrade_latest_with_delta()` 구현
- `main.c` 이벤트 저장 과정에 추가 함수 연결

**결과**

실제 JTAG UART 로그에서 이벤트별 DELTA 출력과 복합 이벤트 DELTA 갱신 결과를 확인하였다.

### 문제 3. 반복 이벤트 발생으로 인한 Record 저장 미완료

**문제**

실제 보드 테스트에서 SHOCK 및 SOUND 이벤트가 짧은 간격으로 반복 발생하였으며, 최신 로그에서 `[RECORD] SAVED` 메시지를 확인하지 못하였다.

**원인 분석**

현재 Event Record는 새로운 독립 이벤트 발생 시 기존 수집을 중단하고 최신 이벤트를 기준으로 기록을 교체하도록 설계되어 있다.

따라서 이벤트가 약 5초보다 짧은 간격으로 반복되면 이후 500개 샘플 수집이 완료되기 전에 새로운 Record가 시작될 수 있다.

**향후 해결 방향**

- 반복 이벤트의 실제 센서 입력 상태 확인
- Event Record 저장 완료 조건 재검토
- 새로운 이벤트 발생 시 기존 Record 처리 정책 검토

**현재 상태**

문제 확인 완료 / 수정은 추후 진행 예정

### 문제 4. 진동 센서의 반복 이벤트 및 값 변동

**문제**

초기 진동 센서 평균값은 1220이었으나 이후 300~800대 측정값이 반복적으로 나타났고, 일부 입력에서는 ADC 최대값인 4095도 확인되었다.

**원인 분석**

초기 평균값을 기준으로 충격 감지를 수행하므로 기준값에서 크게 벗어난 측정값이 지속되면 SHOCK 이벤트가 반복 발생할 수 있다.

다만 실제 물리적 충격이 반복되었는지 센서 입력이 불안정한 것인지는 로그만으로 확정하기 어렵다.

**향후 해결 방향**

- 센서가 고정된 상태에서 ADC 값 확인
- 센서 연결 및 입력 안정성 확인
- 필요시 충격 이벤트 재감지 조건 보완

**현재 상태**

현상 확인 완료 / 추가 실험 필요

### 문제 5. JTAG UART 출력 일부 누락

**문제**

실제 보드 로그에서 다음과 같이 메시지가 중간에 잘리거나 이어지는 현상이 발생하였다.

```text
[HISTORY] Saved ([RECORD] SHOCK | BEFORE
```

**원인 분석**

현재 `uart_print()`는 출력 FIFO에 공간이 없을 때 일정 시간 대기한 뒤 타임아웃이 발생하면 문자열 출력을 중단하는 방식이다.

이벤트 발생 시 다수의 센서 샘플과 History 정보를 연속 출력하면서 출력 데이터가 증가한 것이 원인 중 하나일 가능성이 있다.

**향후 해결 방향**

- 상세 Record 디버그 출력량 축소
- UART 출력 타임아웃 처리 검토
- 로그 출력이 센서 샘플링에 미치는 영향 분석

**현재 상태**

현상 확인 완료 / 추후 수정 예정
