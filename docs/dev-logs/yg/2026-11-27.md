### 작업 3. 경고음에 의한 SOUND 이벤트 재감지 방지

**작업 대상**

- `src/main.c`

**발생 가능 문제**

이벤트 발생 시 Audio-out을 통해 경고음이 출력된다.

출력된 경고음이 마이크 또는 Audio-in으로 다시 입력되면
시스템 자체에서 발생시킨 경고음을 외부 소음으로 판단하여
새로운 SOUND 이벤트를 감지할 가능성이 있다.

이로 인해 다음 문제가 발생할 수 있다.

- SOUND 이벤트 반복 발생
- 실제로 발생하지 않은 복합 이벤트 생성
- 불필요한 Event History 저장
- Event Record 수집 중 새로운 Record 생성
- 위험 단계의 불필요한 상승

**해결 방법**

원본 SensorSample을 직접 변경하지 않고,
이벤트 감지 및 위험 단계 계산에 사용하는 복사본을 생성하였다.

경고음이 활성 상태일 때는 감지용 샘플의 소음값을
초기 소음 평균값으로 대체하도록 수정하였다.

**추가 및 수정 코드**

```c
SensorSample detect_sample = sample;

if (alarm_is_active())
{
    detect_sample.sound_level = sound_average;
}

flags = event_detect(&detect_sample);

current_risk =
    risk_level_update(&detect_sample);
```

경고음이 활성 상태인 경우 감지용 소음 변화량이
0이 되도록 처리하였다.

```text
감지용 SOUND DELTA = sound_average - sound_average

감지용 SOUND DELTA = 0
```

**센서 샘플 사용 구분**

| 기능 | 사용 데이터 |
|---|---|
| Event Detector | detect_sample |
| Risk Level | detect_sample |
| Ring Buffer | sample |
| Event Record | sample |
| Event History DELTA 계산 | sample |
| UART 출력 | sample |
| VGA 센서값 출력 | Ring Buffer에 저장된 원본 sample |

**개선 결과**

경고음이 활성화된 동안 시스템 자체 경고음으로 인해
새로운 SOUND 이벤트 및 잘못된 복합 이벤트가 발생하는
가능성을 줄이도록 수정하였다.

진동 및 조도 측정값은 변경하지 않으므로 기존 SHOCK 및
LIGHT 감지 방식은 유지된다.

또한 실제 측정된 소음값은 원본 SensorSample에 남아 있으므로
Ring Buffer, Event Record, UART 및 VGA의 데이터는
기존과 동일하게 실제 측정값을 사용한다.

**현재 방식의 제한사항**

- 경고음 활성 상태에서는 실제 외부 소음 이벤트도 감지하지 않는다.
- 경고음 종료 직후 잔류 소음에 대한 별도 차단 시간은 적용하지 않았다.
- 감지용 소음값 대체가 기존 SOUND 래치의 해제 조건에 영향을 줄 수 있다.
- 초기 Audio-out 테스트 경고음의 종료 동작을 확인해야 한다.

해당 제한사항은 실제 보드 테스트를 통해 검토할 예정이다.

### 작업 4. SHOCK 이벤트 쿨다운 및 래치 설정 오류 수정

**작업 대상**

- `src/event/event_detector.c`

**발생 가능 문제**

기존 일반 이벤트 확정 함수에서는 이벤트 확정 전에
래치를 설정한 후 쿨다운 조건을 검사하고 있었다.

쿨다운이 종료되지 않은 상태에서 새로운 이상 상태가 감지되면
실제로 이벤트를 확정하지 않았음에도 래치가 설정될 수 있었다.

이 경우 이상 상태가 쿨다운 종료 이후까지 지속되어도
래치 때문에 새로운 이벤트를 감지하지 못할 가능성이 있었다.

**수정 전 코드**

```c
state->latched = true;

if (state->has_event &&
    (uint32_t)(now_ms - state->last_event_ms)
        < EVENT_COOLDOWN_MS)
{
    return false;
}
```

**수정 후 코드**

```c
/*
 * 이벤트 재감지 대기시간 확인
 *
 * 쿨다운이 종료되지 않은 경우
 * 이벤트를 확정하지 않는다.
 *
 * 이때 래치를 설정하지 않아
 * 쿨다운 종료 후에도 감지가 가능하도록 한다.
 */
if (state->has_event &&
    (uint32_t)(now_ms - state->last_event_ms)
        < EVENT_COOLDOWN_MS)
{
    return false;
}

/*
 * 연속 감지 및 쿨다운 조건을 모두
 * 충족한 경우에만 래치를 설정한다.
 */
state->latched = true;

state->has_event = true;
state->last_event_ms = now_ms;

return true;
```

**수정 전후 예상 동작**

| 시간 | 센서 상태 | 수정 전 | 수정 후 |
|---|---|---|---|
| 6000ms | SHOCK 확정 | 이벤트 감지 | 이벤트 감지 |
| 6200ms | 정상 범위 복귀 | 래치 해제 | 래치 해제 |
| 6500ms | 새로운 충격 | 쿨다운 중 | 쿨다운 중 |
| 6510ms | 연속 감지 충족 | 잘못된 래치 설정 가능 | 래치 설정 안 함 |
| 7000ms | 쿨다운 종료 및 충격 지속 | 재감지 누락 가능 | 재감지 가능 |

위 시간은 수정 로직을 설명하기 위한 예시이며
실제 보드 측정 결과는 아니다.

**개선 결과**

이벤트 확정에 필요한 연속 감지 및 쿨다운 조건을
모두 만족했을 때만 래치를 설정하도록 수정하였다.

쿨다운 중 시작된 진동 이상 상태가 쿨다운 종료 이후까지
유지되면 새로운 이벤트로 감지할 수 있도록 개선하였다.

**유지한 기존 기능**

- 초기 평균값 대비 절댓값 변화량 계산
- 연속 2회 감지
- 1000ms 쿨다운
- SOUND 별도 래치 해제 조건
- LIGHT 별도 래치 해제 조건
- 복합 이벤트 비트 플래그 판정
- 기존 Event Detector Public API

### 작업 5. 복합 이벤트 확장 허용 시간 제한

**작업 대상**

- `include/system_config.h`
- `src/main.c`

**발생 가능 문제**

기존 복합 이벤트 확장 로직에서는 Event Record가 수집 중이고
새로운 이벤트 플래그에 기존 이벤트 플래그가 포함되어 있으면
기존 이벤트를 복합 이벤트로 확장할 수 있었다.

그러나 기존 이벤트와 새로운 이벤트 사이의 시간 차이를
확인하지 않아 시간적으로 떨어진 독립 이벤트도
기존 이벤트에 합쳐질 가능성이 있었다.

예를 들어 기존 SHOCK 이벤트 발생 이후 해당 충격이 종료되고,
수초 후 새로운 SHOCK+LIGHT 이벤트가 발생해도
기존 Record 수집 상태에 따라 같은 이벤트로
처리될 가능성이 있었다.

**해결 방법**

최초 이벤트 발생 이후 일정 시간 이내인 경우에만
기존 Record의 복합 이벤트 확장을 허용하도록 수정하였다.

**공통 설정 추가**

```c
#define EVENT_COMBINE_WINDOW_MS 500U
```

**main.c 수정 코드**

```c
if (record_collecting &&
    !event_record_is_saved() &&
    event_record_get_info(&previous) &&
    event_history_get(0U, &latest) &&
    previous.timestamp_ms ==
        latest.timestamp_ms &&
    previous.event_flags ==
        latest.event_flags &&
    flags != previous.event_flags &&
    (uint8_t)(flags & previous.event_flags) ==
        previous.event_flags &&
    (uint32_t)(sample.timestamp_ms -
               previous.timestamp_ms)
        <= EVENT_COMBINE_WINDOW_MS)
```

기존 복합 이벤트 확장 조건은 모두 유지하고
최초 이벤트 발생 시각과 새로운 이벤트 발생 시각의
차이를 확인하는 조건만 추가하였다.

**수정 후 예상 처리**

다른 기존 확장 조건을 모두 만족하는 경우를 기준으로 한다.

| 최초 이벤트 | 새로운 이벤트 | 시간 차이 | 처리 |
|---|---|---:|---|
| 6000ms SHOCK | 6200ms SHOCK+LIGHT | 200ms | 복합 확장 |
| 6000ms SHOCK | 6500ms SHOCK+LIGHT | 500ms | 복합 확장 |
| 6000ms SHOCK | 6600ms SHOCK+LIGHT | 600ms | 독립 이벤트 |
| 6000ms SHOCK | 8500ms SHOCK+LIGHT | 2500ms | 독립 이벤트 |

**개선 결과**

기존 이벤트와 시간적으로 떨어진 새로운 이벤트가
동일한 Event Record에 잘못 합쳐지는 가능성을 줄였다.

복합 이벤트 확장에 성공한 경우 기존 센서 데이터 및
History 개수는 유지하도록 기존 저장 방식을 보존하였다.

**현재 방식의 제한사항**

500ms 조건은 시간 기반의 단순 확장 정책이다.

실제 센서 이벤트의 연속성을 완벽하게 판단하지는 않는다.

500ms 이후에 이어지는 실제 복합 이벤트가 독립 이벤트로
분리되거나, 500ms 이내의 독립 이벤트가 결합될 가능성은
남아 있다.

Event Record 수집 중 새로운 독립 이벤트가 발생했을 때의
기록 교체 정책은 이번 작업에서 변경하지 않았다.

### 작업 7. VGA 실시간 모니터링 화면 DELTA 표시 정리

**작업 대상**

- `src/display/vga.c`

**기존 화면 구성**

```text
SENSOR / VALUE / LIMIT / EXCESS
```

기존 초기 VGA 설계에서는 EXCESS 항목을 이용하여
이벤트 임계값을 초과한 변화량을 표시하도록 하였다.

그러나 이벤트 임계값을 넘지 않은 상태에서도
현재 센서값이 초기 기준값보다 얼마나 증가하거나
감소했는지 확인할 수 있도록 표시 방식을 정리하였다.

**최종 화면 구성**

```text
SENSOR / VALUE / LIMIT / DELTA
```

**DELTA 계산 방식**

```c
static int32_t signed_delta_u16(
    uint16_t value,
    uint16_t limit)
{
    return (int32_t)value - (int32_t)limit;
}
```

```text
DELTA = VALUE - LIMIT
```

**출력 형식**

```c
(void)snprintf(
    msg,
    sizeof(msg),
    "%+ld",
    (long)delta
);
```

**최종 표시 항목**

| 항목 | 설명 |
|---|---|
| VALUE | 최신 실제 센서 측정값 |
| LIMIT | 초기 Calibration 평균값 |
| DELTA | 현재값 - 초기 평균값 |
| RISK | 현재 위험 단계 |
| UPTIME | 시스템 실행 시간 |
| THRESHOLD | 센서별 이벤트 감지 임계값 |

**표시 예시**

| VALUE | LIMIT | DELTA |
|---:|---:|---:|
| 800 | 1220 | -420 |
| 1250 | 1220 | +30 |
| 1220 | 1220 | +0 |

위 수치는 계산 방식을 설명하기 위한 예시이다.

**개선 결과**

초기 평균값과 현재 센서값의 차이를
증가 및 감소 방향과 함께 확인할 수 있도록 정리하였다.

실시간 화면에서 사용하는 DELTA는
이벤트 감지 임계값을 차감하지 않는다.

센서별 감지 임계값은 별도의 THRESHOLD 항목에서 표시한다.

실시간 DELTA의 부호 있는 계산 방식은
최종 VGA 코드에서 그대로 유지하였다.

### 작업 8. VGA History DELTA의 불필요한 + 부호 제거

**작업 대상**

- `src/display/vga.c`

**발생 가능 문제**

Event History에는 이벤트 발생 당시 초기 평균값 대비
절댓값 변화량이 저장된다.

그러나 기존 History 화면은 절댓값 앞에
항상 + 부호를 붙여 출력하고 있었다.

실제 센서값이 초기 평균값보다 감소한 경우에도
증가한 것으로 표시될 수 있어 의미상 혼동이 발생하였다.

**수정 전 코드**

```c
(void)snprintf(
    msg,
    sizeof(msg),
    "+%u",
    (unsigned)entry.delta
);
```

**수정 후 코드**

```c
/*
 * History DELTA는 절댓값 변화량을 사용한다.
 *
 * 실시간 화면과 달리 증가 및 감소 방향을
 * 구분하지 않고 변화량의 크기만 표시한다.
 *
 * 양수 방향으로 오해하지 않도록
 * + 부호 없이 숫자만 출력한다.
 */
(void)snprintf(
    msg,
    sizeof(msg),
    "%u",
    (unsigned)entry.delta
);
```

**수정 전후 표시 비교**

| 실제 변화량 | 실시간 DELTA | 기존 History | 수정 History |
|---:|---:|---:|---:|
| -420 | -420 | +420 | 420 |
| +350 | +350 | +350 | 350 |
| -1800 | -1800 | +1800 | 1800 |

**해결 방식 결정**

History에도 증가 및 감소 방향을 저장하는 방식을 검토하였다.

그러나 해당 방식은 Event History 자료형, 저장 함수,
main.c DELTA 계산 및 VGA 출력까지 함께 변경해야 하므로
기존 저장 구조에 영향을 줄 수 있었다.

따라서 기존 절댓값 저장 방식은 유지하고,
VGA에서 불필요한 + 부호만 제거하는 방식으로 결정하였다.

**개선 결과**

실시간 화면과 History 화면의 DELTA 의미를 구분하였다.

| 화면 | DELTA 의미 |
|---|---|
| Real-time | 부호 있는 현재 변화량 |
| History | 저장된 절댓값 변화량 |

Event History의 기존 자료형, 저장 용량 및 API는
변경하지 않았다.

### 작업 9. VGA NO SAMPLE 출력 시 위험 단계 잔상 제거

**작업 대상**

- `src/display/vga.c`

**발생 가능 문제**

VGA 실시간 화면은 센서 데이터를 조회하지 못했을 때
위험 단계 위치에 NO SAMPLE을 출력한다.

기존 코드는 NO SAMPLE 문구 출력 이후 바로 return하여
함수 아래쪽의 위험 단계 픽셀 초기화 코드가
실행되지 않는 구조였다.

VGA의 위험 단계 문구는 픽셀 버퍼를 사용하고,
NO SAMPLE은 문자 버퍼를 사용한다.

따라서 문자 버퍼에 NO SAMPLE을 출력하는 것만으로는
기존 NORMAL, CAUTION, DANGER의 색상 픽셀이
제거되지 않을 가능성이 있었다.

**해결 방법**

센서 샘플 조회에 실패한 경우 기존 위험 단계의
픽셀 영역을 배경색으로 초기화하도록 수정하였다.

**추가 코드**

```c
/*
 * 이전 위험 단계의 색상 글자 제거
 *
 * 샘플 조회 실패 시 기존 위험 표시가
 * NO SAMPLE과 겹치는 현상을 방지한다.
 */
pixels_rect(
    100U, 204U,
    230U, 225U,
    C_BG
);
```

**수정 후 처리 순서**

```text
최신 센서 샘플 조회
        |
        v
샘플 조회 실패
        |
        v
VALUE / LIMIT / DELTA를 ---로 표시
        |
        v
기존 위험 단계 픽셀 제거
        |
        v
NO SAMPLE 출력
        |
        v
현재 화면 갱신 종료
```

**개선 결과**

샘플 조회 실패 시 이전 위험 단계의 색상 글자가
NO SAMPLE과 함께 표시될 가능성을 제거하도록 수정하였다.

정상적으로 센서 샘플을 다시 조회하면
기존 위험 단계 갱신 로직을 통해 현재 상태가 출력된다.

기존 화면 좌표 및 배경색을 사용하므로
전체 VGA 화면 디자인은 변경하지 않았다.

실제 잔상 제거 및 정상 화면 복귀 여부는
VGA 모니터 연결 후 검증할 예정이다.

### 작업 10. VGA History 화면 SAVED 표시 변경

**작업 대상**

- `src/display/vga.c`

**발생 가능 문제**

기존 History 화면의 오른쪽 상단에는
SAVED 문구가 고정적으로 표시되어 있었다.

저장된 이벤트가 없거나 Event Record가 아직
수집 중인 경우에도 SAVED가 표시될 수 있으므로
사용자가 저장 완료 상태로 오해할 가능성이 있었다.

**해결 방법**

저장 완료 상태를 나타내는 SAVED 대신
현재 화면의 종류를 나타내는 HISTORY로 변경하였다.

**수정 전**

```c
color_word(
    250U, 12U,
    "SAVED", C_GREEN
);
```

**수정 후**

```c
color_word(
    226U, 12U,
    "HISTORY", C_GREEN
);
```

**추가 확인 사항**

기존 VGA 색상 글꼴은 일부 영문 대문자만 정의되어 있다.

HISTORY를 출력하는 데 필요한 H와 Y 글꼴이
기존 배열에 존재하지 않는 것을 확인하였다.

따라서 다음 글꼴 데이터를 추가하였다.

```c
{'H', 0x11,0x11,0x11,0x1F,0x11,0x11,0x11},

{'Y', 0x11,0x11,0x0A,0x04,0x04,0x04,0x04}
```

기존 글꼴 데이터는 모두 유지하였다.

**출력 좌표 조정**

기존 SAVED는 5글자이며 HISTORY는 7글자이다.

VGA 색상 글자는 글자당 12픽셀 간격으로 출력되므로
두 글자 증가에 맞추어 시작 위치를 24픽셀 왼쪽으로
이동하였다.

```text
기존 시작 좌표: 250

변경 시작 좌표: 226

이동 거리: 24 pixels
```

**개선 결과**

History 화면의 오른쪽 상단 문구가 실제 저장 완료 여부가
아닌 현재 화면 종류를 의미하도록 변경하였다.

실제 저장된 이벤트의 개수는 기존 STORED 항목으로
확인할 수 있도록 유지하였다.

별도의 SAVED / EMPTY 상태 분기 로직은 추가하지 않았다.

기존 녹색 표시 및 오른쪽 여백은 유지하도록 작성하였다.

실제 HISTORY 글꼴 출력 및 화면 잘림 여부는
VGA 모니터에서 확인할 예정이다.

**SensorSample 원문 선언 확인**

```c
typedef struct {
    uint32_t timestamp_ms;
    uint16_t vibration;
    uint16_t sound_level;
    uint16_t light;
} SensorSample;
```

기존 원문에 정의된 필드 순서를 문서에 보존하였다.

실제 공통 헤더의 최신 선언은 추후 최종 확인한다.

이번 문서 정리 과정에서 구조체의 실행 코드는
임의로 변경하지 않았다.

**기존 API 계약 복원**

```c
bool sensor_init(void);
bool sensor_read(SensorSample *out);

bool timer_init(void);
uint32_t timer_get_ms(void);
bool timer_take_sample_tick(void);

bool interrupt_init(void);
void interrupt_enable(void);
void interrupt_disable(void);

void event_record_clear(void);
void event_history_clear(void);

void system_state_init(void);
SystemState system_state_get(void);
void system_state_set(SystemState next);

uint8_t event_classify(uint8_t event_flags);
```

위 선언은 기존 api-contract.md에 정의된 계약을
보존하기 위한 것이다.

기존 계약에 존재한다는 이유만으로 최신 소스에
모든 함수가 실제 구현되어 있다고 단정하지 않았다.

**추가 반영한 신규 내용**

- 감지용 센서 샘플 분리

  추가 협의 대상으로 구분하였다.

**개선 결과**

기존 계획과 현재 구현의 차이가 문서에 명시되도록 하였다.

아직 해결되지 않은 저장 정책을 수정 완료 상태로

## 5. 발생한 문제 및 해결

### 문제 1. 센서 이벤트 감지 민감도

**문제**

기존 진동 및 소음 감지 임계값으로 인해 작은 변화에도
이벤트가 발생할 가능성이 있었다.

**해결**

SHOCK 감지 임계값을 400에서 800으로 변경하고
SOUND 감지 임계값을 900에서 1800으로 변경하였다.

**현재 상태**

코드 수정 완료 / 실제 민감도 검증 필요

### 문제 2. 조도 감지 및 해제 조건 중첩

**문제**

기존 LIGHT 감지 임계값 50과 해제 임계값 75의
조건이 중첩되는 구간이 존재하였다.

**해결**

감지 임계값을 150으로 변경하고
해제 임계값 75는 유지하였다.

**현재 상태**

코드 수정 완료 / 보드 테스트 필요

### 문제 3. 경고음에 의한 SOUND 재감지

**문제**

Audio-out 경고음이 Audio-in에 입력되면
새로운 SOUND 이벤트로 감지될 가능성이 있었다.

**해결**

감지용 SensorSample 복사본을 생성하고
경고음 활성 중 소음값을 초기 평균값으로 대체하였다.

원본 센서 데이터는 유지하였다.

**현재 상태**

코드 수정 완료 / 보드 테스트 필요

### 문제 4. SHOCK 쿨다운 중 잘못된 래치 설정

**문제**

쿨다운 검사를 수행하기 전에 래치를 설정하여
이상 상태가 지속되는 경우 재감지가 누락될 수 있었다.

**해결**

쿨다운 검사 이후에만 래치를 설정하도록 변경하였다.

**현재 상태**

코드 수정 완료 / 보드 테스트 필요

### 문제 5. 시간적으로 떨어진 이벤트의 복합 확장

**문제**

최초 이벤트와 새로운 이벤트 사이의 시간 차이를
고려하지 않아 독립 이벤트가 합쳐질 가능성이 있었다.

**해결**

기존 확장 조건에 EVENT_COMBINE_WINDOW_MS를 추가하였다.

500ms 이내에서만 기존 Record의 복합 확장을 허용한다.

**현재 상태**

코드 수정 완료 / 보드 테스트 필요

### 문제 6. VGA History DELTA의 부호 오류

**문제**

절댓값 DELTA 앞에 항상 + 부호를 표시하여
실제 센서값의 증가 방향으로 오해할 수 있었다.

**해결**

출력 형식을 +%u에서 %u로 변경하였다.

기존 절댓값 저장 구조는 유지하였다.

**현재 상태**

코드 수정 확인 완료 / VGA 모니터 검증 필요

### 문제 7. VGA NO SAMPLE 위험 단계 잔상

현재 구현과의 차이로 정리하였다.

KEY1의 현재 데이터 보존 동작을 명확하게 반영하였다.

**현재 상태**

문서상 차이 분석 및 반영 완료 /
Record 최종 보호 및 교체 정책은 미해결
